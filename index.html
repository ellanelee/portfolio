How I Work

DEFINE → BUILD → VERIFY → IMPROVE

IT기획 시절부터 이어온 일하는 방식입니다. 요구사항을 명확히 정의하는 습관이, 지금은 코드 품질로 이어지고 있습니다.

01
DEFINE
요구사항과 문제를 구조화해서 정의합니다.
02
BUILD
설계에 맞춰 프론트·백엔드를 직접 구현합니다.
03
VERIFY
실제 사용자 흐름과 데이터 구조의 차이를 검증합니다.
04
IMPROVE
피드백을 반영해 다시 DEFINE으로 돌아갑니다.

04 → 01 로 이어지는 반복 개선 루프
